# 0011. `liquid/lfm-2.5-2.6b:free` as the default model, `openrouter/free` as fallback

- Status: accepted
- Date: 2026-09-21
- Deciders: solo (Luiz Wagner)

## Context

Backlog item 1 (Phase 1) required picking the default `OPENROUTER_MODEL`
from real, timed queries against the netbook — not the static table in
`architecture.md` §8.2 — with the 8-second Alexa deadline (§5.3) as the
bar. `relay/measure_latency.py` (new, reuses `app.py`'s exact request
shape/timeouts) was run against four candidates from OpenRouter's live
`:free` catalog:

| Model | Result |
|---|---|
| `nvidia/nemotron-3.5-lightning:free` | Disqualified before our own test ran — the OpenRouter dashboard showed 40–80s time-to-first-token, ~10x over budget. |
| `google/gemma-4-26b-a4b-it:free` | 100% HTTP 429 across two separate runs (20 calls total), including a run with 2s spacing between requests — ruling out our own request pacing as the cause. |
| `qwen/qwen3.8-27b:free` | 100% HTTP 429 across one run (10 calls, 2s spacing). |
| `liquid/lfm-2.5-2.6b:free` | 17/19 successful calls across two runs. min=0.54–0.98s, avg=0.99–1.50s, p90=1.55–3.20s, max=1.55–3.20s. Comfortably under the 8s deadline every time. |

The pattern across the two larger models (26B/27B-class) failing 100%
while the smallest candidate (2.6B) succeeded consistently isn't
coincidence — free-tier serving capacity is scarcer for bigger models
(more compute demand, less spare capacity to give away for free), and
`architecture.md` §8.1 already documents free endpoints as "best-effort
capacity, subject to queuing and provider throttling." A `GET
/api/v1/key` check (via a throwaway script on the netbook, real key never
exposed to the assistant) also confirmed the account already has the
one-time $10 credit applied — daily cap is 1,000/day, not 50/day, with
975 remaining at check time. Quota headroom was never the actual
constraint; provider-side capacity throttling on larger models was.

## Decision

- `OPENROUTER_MODEL=liquid/lfm-2.5-2.6b:free` — fastest and only
  consistently-available candidate tested.
- `OPENROUTER_FALLBACK_MODEL=openrouter/free` — the free-models router
  (`architecture.md` §8.2: "routes to whichever free provider currently
  has capacity"), which is exactly the right tool for the 429-under-load
  failure mode observed on the larger candidates, not just a generic
  backstop.

These values go in the real `.env` (not `.env.example`, and not edited by
the assistant — the user sets them directly, per the standing "never
read/write `.env`" rule from ADR 0008).

## Consequences

### Positive
- Closes backlog item 1 with a decision backed by real, repeated
  measurements on the actual netbook network path, not the architecture
  doc's static table.
- The chosen fallback isn't generic — it specifically targets the
  observed failure mode (capacity 429s on less-available models), so a
  future model swap that hits the same issue is already covered.
- `relay/measure_latency.py` is a reusable tool if candidates need
  re-testing later (model catalog churns, per `architecture.md` §8.2).

### Negative / trade-offs
- LFM2.5 is a small (2.6B) model — untested here for answer *quality*,
  only latency/availability. If early real-Echo usage shows weak answers,
  revisiting model choice is fair game (the Phase 4 backlog item already
  flags this same speed-vs-accuracy concern for the local llama.cpp
  candidate — see napkin Domain Behavior Guardrails).
- Gemma and Qwen weren't proven *bad* models, just unavailable at test
  time — free-tier capacity fluctuates, so this decision may be worth
  revisiting if LFM2.5 itself starts showing 429s in practice.
- `openrouter/free`'s routing means the household has no control over
  which specific model answers on a fallback — tone/quality may vary
  request to request (architecture.md §8.2 flags this as its known
  trade-off, "good fallback value, don't make it primary").

### Follow-ups
- If real Echo usage surfaces quality complaints, re-run
  `measure_latency.py` against a broader candidate set and weigh quality
  against latency, not latency alone.

## Alternatives considered

- **`google/gemma-4-26b-a4b-it:free` or `qwen/qwen3.8-27b:free` as
  primary** — rejected: both failed 100% of live test calls with HTTP 429
  across repeated runs; not viable regardless of any quality upside.
- **`nvidia/nemotron-3.5-lightning:free`** — rejected outright on
  dashboard-reported 40–80s time-to-first-token, ~10x the 8s deadline.
- **`openrouter/free` as the primary model, not just the fallback** —
  considered and declined: gives up control over which model answers on
  every request, not just as a capacity backstop; kept as fallback-only
  per its documented intended use.
