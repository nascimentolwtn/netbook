Netbook Repository: Full Overview

This page uses short, plain sentences. This style is close to ASD-STE100, the Simplified Technical English standard. The goal is a text that is easy to read and easy to translate.

What This Repository Is

This repository holds the setup for one old netbook computer. The netbook has four jobs. Each job is its own project in this repository.

The four projects:
  1. Syncthing — collects photos from family phones.
  2. Digital Frame — shows those photos on a screen, as a slideshow.
  3. dupe-sweep mvp2-remote — finds and removes duplicate photos in a large archive.
  4. alexa-talk-pal — lets an Alexa Echo device ask an AI model and speak the answer.

The first three projects form one photo system. The fourth project is separate. It does not touch photos. It only answers spoken questions.

Note on what lives here: this repository holds code and setup files. It does not hold the family photos. It does not hold the 360GB archive. Photos stay on the netbook's drives. Only the scripts, configuration, and history live in this repository.

1. Syncthing: How Photos Arrive

Syncthing is a program. The program copies files between devices. Syncthing does not need the internet. Syncthing works over the home WiFi network.

The netbook runs Syncthing all the time. The netbook is the hub. Each family phone also runs Syncthing. Each phone sends its photos to the hub.

Rules Syncthing Follows

  1. Each device has one fixed ID. The ID comes from a security certificate on that device.
  2. Two devices must trust each other before they share files. You add the other device's ID on both sides.
  3. Each shared folder has one fixed ID too. The folder name can change. The folder ID must stay the same.
  4. If a device ID is new to the hub, the hub rejects the connection. You must add the new ID first.
Common problem: you move to a new phone. The new phone gets a new ID. The hub does not know the new ID yet. The connection fails until you add the new phone's ID to the hub, and share the correct folder with it.

2. Digital Frame: How Photos Show on the Screen

Digital Frame is a script. The script runs on the netbook. The script shows photos on a screen, one at a time, in a loop. The script uses a small program named feh. This program draws the image on the screen.

Steps in the Loop

  1. Digital Frame looks at the photo folders.
  2. Digital Frame picks a folder. Digital Frame gives more chances to big folders, and fewer chances to small folders. This rule stops one small folder from showing too often.
  3. Digital Frame picks one photo from that folder.
  4. Digital Frame resizes the photo to fit the screen. Digital Frame does this step early, for a few photos ahead. This step keeps the slideshow smooth on old, slow hardware.
  5. Digital Frame shows the photo for a fixed time. The default time is 15 seconds.
  6. Digital Frame repeats the loop.

Other Safety Steps

  • Digital Frame writes a log file for crashes. The log file keeps the last 500 entries.
  • Digital Frame writes a log file for recent actions too. This file keeps the last 50 entries.
  • Digital Frame turns off the screen's sleep function. The screen stays on at all times.
  • You can pause the slideshow with the space key. You can delete the current photo with the d key. A deleted photo moves to a holding folder. The script does not erase the photo right away.

How Syncthing and Digital Frame Connect

Syncthing and Digital Frame do not talk to each other directly. They connect through one shared folder, for example Photos_LW. Syncthing writes new photos into the folder. Digital Frame reads photos from the same folder. This design keeps each part simple. Each part does one job.

3. dupe-sweep mvp2-remote: How the Archive Gets Clean

The netbook holds a large archive of photos. The archive size is about 360GB. Many photos in the archive are duplicates. dupe-sweep finds these duplicates and helps a person remove them.

dupe-sweep does not run on the netbook. dupe-sweep runs on a Windows PC. The PC does not copy the whole archive first. A full copy would take weeks and waste disk space. Instead, the PC reads the archive over the network, through SSH.

Steps dupe-sweep Takes

  1. The PC connects to the netbook over SSH.
  2. The PC reads a small thumbnail from inside each photo file, not the full photo. This step makes scanning about 19 times faster.
  3. The PC turns each thumbnail into a short code, called a hash.
  4. The PC groups photos with matching hashes, and close time stamps, as likely duplicates.
  5. A person opens a browser window, and reviews each group.
  6. The person keeps or deletes each photo. The program moves a deleted photo to a holding folder, named _to_delete. The program does not erase the photo right away.
Note: the dupe-sweep program's own code does not live in this repository. The code lives only on the Windows PC. This repository only describes how dupe-sweep connects to the netbook.

4. alexa-talk-pal: How the Echo Gets an AI Answer

alexa-talk-pal is a separate project. It is not part of the photo system. It lets a family member ask an Alexa Echo device a question, in free, natural speech. A small relay program, running on the netbook, asks an AI model for the answer.

Steps in the Path

  1. A family member speaks to the Echo device.
  2. The Echo device sends the words to the Alexa Skills Kit, a cloud service run by Amazon.
  3. The Alexa Skills Kit sends the request through a tunnel, named ngrok, to the netbook.
  4. A relay program on the netbook receives the request. The relay program is a small Flask web server.
  5. The relay program asks an AI model for an answer. The AI model runs on OpenRouter, a cloud service, or on a local program on another computer.
  6. The relay program sends the answer back, through the same path, to the Echo device.
  7. The Echo device speaks the answer out loud.
Warning for this project: the running relay code on the netbook is a plain file copy, not a git checkout. A commit in this repository does not update the live program by itself. After a code change, copy the changed files to the netbook by hand, then restart the relay service.
